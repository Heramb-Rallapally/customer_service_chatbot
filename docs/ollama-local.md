# Local Ollama with Oracle 23ai

The runtime defaults to local Ollama for generation and embeddings while
preserving Oracle Database 23ai and LangChain OracleVS as the vector store.

```text
documents → chunking → Ollama nomic-embed-text (768)
          → OracleVS / Oracle 23ai COSINE search
          → retrieved knowledge → Ollama llama3.2:3b → ChatResponse
```

## Setup

Start Ollama and install the models:

```bash
ollama serve
ollama pull llama3.2:3b
ollama pull nomic-embed-text
```

Configure the process (the shown model/provider values are defaults):

```bash
export LLM_PROVIDER=ollama
export EMBEDDING_PROVIDER=ollama
export OLLAMA_BASE_URL=http://127.0.0.1:11434
export OLLAMA_TIMEOUT_SECONDS=120
export LLM_MODEL=llama3.2:3b
export EMBEDDING_MODEL=nomic-embed-text
export EMBEDDING_DIMENSION=768
export ORACLE_DB_USER=...
export ORACLE_DB_PASSWORD=...
export ORACLE_DB_DSN=...
export ORACLEVS_TABLE=SUPPORT_KNOWLEDGE_OLLAMA
```

No `.env` file is loaded automatically. Check local availability without
contacting Oracle:

```bash
python -m src.ollama.health
```

The application also checks required Ollama models during its lazy first-chat
composition. `/health` remains a process-liveness endpoint and intentionally
does not contact Ollama or Oracle.

## Oracle vector dimension and re-indexing

The installed `nomic-embed-text` model returns 768-dimensional vectors.
LangChain Community 0.3.31 creates the OracleVS column as
`VECTOR(768, FLOAT32)`. Before OracleVS starts, the application inspects an
existing table's DDL and refuses an `EMBEDDING` column dimension mismatch.

Do not reuse rows generated by another embedding model. Dimension equality
alone does not make embedding spaces compatible. Use a newly provisioned or
operator-reset table and run the existing ingestion/indexing path to rebuild
all knowledge vectors. The application never silently alters or drops a table.

## Restoring OCI Generative AI

The existing OCI adapters and SDK pin are retained. Set the desired provider
to `oci`, configure the matching OCI model ID in `LLM_MODEL` or
`EMBEDDING_MODEL`, set `EMBEDDING_DIMENSION` for that model, and provide
`OCI_COMPARTMENT_ID` plus the normal OCI profile/endpoint configuration. LLM
and embedding providers may be selected independently.

## Live integration test

The normal suite is credential-free. To exercise real Ollama embeddings,
Oracle insertion/search, and Ollama generation against an isolated table:

```bash
RUN_OLLAMA_ORACLE_INTEGRATION=1 \
ORACLEVS_INTEGRATION_TABLE=SUPPORT_KNOWLEDGE_OLLAMA_TEST \
python -m pytest tests/integration/test_ollama_oraclevs_live.py
```

The Oracle credential variables above must also be present. The test is skipped
otherwise and no live Oracle compatibility is claimed.
