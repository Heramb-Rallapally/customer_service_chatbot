# Durable conversation memory

`ConversationEngine` continues to depend on the small `ConversationMemory`
contract (`load`, `save`, and `get_summary`). `InMemoryConversationMemory` is
kept for unit tests and local development; it is process-local, non-durable,
and unsuitable for multiple workers or application instances.

## Oracle-backed production memory

Set `ORACLE_CONVERSATION_TABLE` to a provisioned Oracle table name to select
`OracleConversationMemory` in `create_application()`. It reuses the existing
Oracle connection and credentials (`ORACLE_DB_USER`, `ORACLE_DB_PASSWORD`, and
`ORACLE_DB_DSN`); it adds no database technology or credentials.

Run [oracle-conversation-memory.sql](oracle-conversation-memory.sql) through
the normal database deployment process before enabling the setting. The
application does not create or alter tables at startup.

The table stores a JSON representation generated by
`ConversationState.model_dump(mode="json")`, the optional summary, ownership
ID, version, and unambiguous Oracle `TIMESTAMP WITH TIME ZONE` creation/update
timestamps. Deserialization validates JSON with `ConversationState`; malformed
stored state raises `ConversationPersistenceError` rather than being silently
discarded.
Deserialization accepts both textual CLOB values and the native Python JSON
object representation returned by Oracle Database 23ai thin-mode connections.

## Concurrency

Durable memory exposes `load_with_version()` and `save_with_version()`. The
engine uses those methods when present:

```text
load version N → process one turn → UPDATE ... WHERE version = N → version N+1
```

An affected-row count of zero raises `ConversationConflictError` when the row
still exists, or `ConversationNotFoundError` when it does not. This prevents a
stale request from overwriting a newer turn. The legacy `load()` then `save()`
sequence is also safe: `load()` retains its version only for the returned state
object. A newly constructed state can be inserted with `save()`, but an
existing state that was not loaded first is rejected rather than silently
becoming a last-write-wins write.

Current scope does not retry a conflicted customer turn automatically; a later
API/deployment step can map that typed conflict to an appropriate retryable HTTP
response. Live Oracle behavior must be validated against provisioned
infrastructure separately from the credential-free tests.
